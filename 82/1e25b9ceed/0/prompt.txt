# 플랜: 캐릭터 스프라이트 해상도 통일 (208×312px)

## Context
`public/assets/players/`의 64개 WebP 파일이 4가지 해상도(256×256, 208×312, 768×1344, 832×1248)로 혼재한다.
게임 내에서는 Phaser가 모두 강제 스케일링하므로 표시 상 문제는 없지만, 파일 크기 불균형(~9KB vs ~90KB)과 로딩 시간 차이가 존재한다.
목표: 모든 파일을 **208×312px**으로 통일하여 메모리·로딩 일관성 확보.

## 수행 순서

### 1단계: 백업
```bash
mkdir -p public/assets/players_backup
cp public/assets/players/*.webp public/assets/players_backup/
```
- 원본을 `public/assets/players_backup/`에 보존
- 코드 변경 없음 (백업 폴더는 빌드에 포함되지 않아도 됨)

### 2단계: ImageMagick 일괄 리사이즈
```bash
for f in public/assets/players/*.webp; do
  convert "$f" \
    -resize 208x312 \
    -gravity center \
    -background none \
    -extent 208x312 \
    "$f"
done
```
- `-resize 208x312`: 비율 유지하며 208×312 안에 맞춤 (강제 왜곡 없음)
- `-gravity center -background none -extent 208x312`: 투명 배경으로 패딩하여 캔버스를 정확히 208×312로 확장
- `-background none`: WebP 투명도(알파 채널) 유지
- ImageMagick이 메모리에 전체 로드 후 쓰기 → 동일 파일 덮어쓰기 안전

### 3단계: 코드 변경 없음
- `Player.ts`의 히트박스 계산이 이미 `scaleX/scaleY` 역산 방식이므로 어떤 해상도든 자동 대응
- `CharacterSelectScene.ts`, `GameScene.ts` 모두 `setDisplaySize()` 고정값 사용 → 수정 불필요

## 대상 파일
- `public/assets/players/*.webp` — 64개 전체

## 변경하지 않는 것
- `src/` 하위 모든 TypeScript 파일
- `public/assets/` 내 players 외 폴더

## 검증
1. 리사이즈 후 `file public/assets/players/*.webp` 로 모든 파일이 208×312인지 확인
2. `npm run dev` → 게임 실행 후 캐릭터 스프라이트 정상 표시 확인
3. `npm run build` → 빌드 오류 없는지 확인
