# 레드 참새 — 위를 보는 시트 배선 준비

composer(w8) 결과가 오기 전 단계다. **시트는 만들지 않았다.**

## 1. 전환 지점 설계

발사는 `RedAbility.launch()` 에서 일어난다. 궤도 스프라이트를 **재사용**해서
`shots` 로 옮기는 구조라, 지금은 `setRotation(-0.35)` 로 머리를 든 척만 하고 있다.
그 한 줄이 위 보는 시트로 바뀔 자리다.

```
궤도(옆모습)  ──launch()──>  발사(위 보는 모습)
              ^ 여기서 텍스처 키를 갈아 끼운다
```

**딱 갈아 끼우면 튄다.** 세 가지를 겹쳐 덮는다.

1. **프레임 위상 유지** — 옆/위 시트가 같은 4프레임 날갯짓이면 현재 프레임 번호를
   그대로 옮겨 준다 (`anims.setProgress` 또는 `startFrame`). 날개가 안 끊긴다.
   → **composer 조건 A**
2. **90ms 교차 페이드** — 같은 자리에 위 보는 스프라이트를 알파 0→1 로 띄우고
   옆모습을 1→0 으로 내린다. 스프라이트 한 장이 잠깐 더 뜰 뿐이고 (동시 최대 5),
   그동안 참새는 `sparrowSpeed 620px/s` 로 올라가므로 잔상처럼 읽힌다.
   새 파라미터 `sparrowTurnMs: 90` (0 이면 즉시 교체).
3. **회전 제거** — 위 보는 시트가 오면 `setRotation(-0.35)` 는 지운다.
   그림이 이미 위를 보므로 두 번 기울면 어색하다.

배선에 필요한 변종 이름은 `ob.texture.key` 에서 되짚을 수 있다
(`fxpick_sparrow_cap_128x128` → `cap`). `Orbiter` 에 필드를 미리 만들어 두지 않았다 —
쓰지도 않을 필드를 넣는 것보다 시트가 온 뒤 한 줄로 끝내는 게 낫다.

## 2. composer 에게 요구할 조건 (w1 이 전달)

**A. 프레임 구성**
- 128×128, **4프레임**, 가로 한 줄 (512×128) — 옆모습 시트와 같은 규격
- **프레임 i 의 날갯짓 위상이 옆모습 시트의 프레임 i 와 같아야 한다.**
  (0=윗짓 시작, 1=중간, 2=아랫짓, 3=중간 — 옆모습과 동일 순서)
  이게 맞아야 발사 순간 날개가 안 끊긴다

**B. 프레임 안 배치 — 이게 제일 중요하다**
- 옆모습 시트 5장은 전부 **몸통 bbox 중심이 (63.5, 63.5)** 로 맞춰져 있다.
  위 보는 시트도 **같은 중심**이어야 한다. 어긋나면 발사 순간 참새가 튄다
- 몸통 bbox 봉투: **가로 ≤ 95px, 세로 ≤ 113px**
  (옆모습의 113×95 를 90도 돌린 값. 코드가 균등 배율 32/128 을 쓰므로 이 봉투를
  지켜야 **보이는 덩치가 안 변한다** — 표시로 23.8×28.2px)
- 머리가 **프레임 위쪽**을 향한다 (진행 방향 = 위)

**C. 그림**
- 배경 완전 투명, 그림자 굽지 말 것
- 옆모습 짝과 **같은 팔레트·같은 광원**. 교체 순간 색이 바뀌면 안 된다
- 변종 5종 각각: `cap` · `goggles` · `cape` · `scarf` · `helmet`
  (모자·고글·망토·목도리·헬멧이 위에서도 알아보여야 한다 — 이게 탄약 개체 구분이다)

**D. 파일명**
- `sparrow_<변종>_up_128x128.png` (예: `sparrow_cap_up_128x128.png`)
- `public/assets/fx/sheets/` 에 넣는다.
  `_128x128` 접미사에서 프레임 크기를 읽으므로 이름을 지켜야 한다

## 3. 판정 반경 — `sparrowHitR: 22` 그대로 둔다

주석이 "참새 반폭 + 똥 반폭" 이라고 돼 있었는데 **틀린 설명이었다.** 실측:

| | 참새 반폭 | 똥 반폭 | 닿기만 해도 맞는 값 |
|---|---|---|---|
| 옆모습 (지금) | 14.1px | 20.0px | **34.1px** |
| 위 보는 모습 (예정) | 11.9px | 20.0px | **31.9px** |

`22` 는 둘 다보다 **좁다** — 참새가 똥에 제대로 겹쳐야 맞는 조율값이다
(빗나가도 소모되는 규칙과 맞물린 난도). 폭이 좁아져도 31.9 > 22 라 **그대로 유효**하다.
주석을 실측값으로 고쳤다.

## 4. VRAM — 둘 다 올린다

| | 크기 |
|---|---|
| 참새 옆모습 5장 (512×128) | 1.25MB |
| 티라노 (1536×192) | 1.12MB |
| 로봇 (1152×192) | 0.84MB |
| **현재 합계** | **3.22MB** |
| 위 보는 5장 (512×128) | +1.25MB |
| **이후 합계** | **4.47MB** |

**둘 다 preload 한다.** 궤도(옆)와 발사(위)가 동시에 화면에 있으므로 어느 한쪽만
올릴 수 없고, 첫 발사가 50점(`sparrowInterval`)이라 아주 이르다 — 그때 로딩하면
그 프레임이 밀린다 (테드에서 파동 텍스처로 겪은 것과 같은 함정).

`RED_SHEETS` 가 `character.ts` 의 `extraFxSheets` 에 그대로 들어가고, 그 배열은
`abilityParams.ts` 에 있다 → **`character.ts` 를 건드리지 않고** 시트를 추가할 수 있다.
레드를 고른 판에서만 올라가므로 다른 캐릭터의 VRAM 은 0 이다.
