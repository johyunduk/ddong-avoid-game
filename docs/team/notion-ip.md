# Notion IP 허브 — 설계와 이관 계획

Notion 은 **회사 문서**다. 읽는 사람은 대표와 앞으로 뽑을 실무진이다.
에이전트용 작업 문서(어떻게·어느 파일)는 저장소에 둔다 — 섞지 않는다.

## 원칙

1. **한 항목 = 한 페이지.** 캐릭터 한 명, 곡 하나, 설정 항목 하나가 각자 페이지다. 한 문서에 여러 명을 몰아 적지 않는다
2. **사실은 한 곳에만.** 다른 페이지는 그 사실을 **관계 속성으로 연결**한다. 다시 적지 않는다
3. **정사(canon) 상태.** IP 항목은 전부 `정사` 속성(`확정 / 초안 / 폐기`)을 가진다.
   에이전트가 쓴 것은 전부 `초안`. **`확정` 으로 바꾸는 건 대표만 한다**
4. **주인이 갈린다.**
   - 설정(외형·성격·목소리·스토리·가사) → **Notion 이 기준**
   - 게임 데이터(ID·등급·능력 수치·에셋 경로) → **저장소가 기준** (`src/`)
   - 제작 진행 상태 → **저장소가 기준** (`production/*.yaml`). Notion 에는 요약만

## 작성 규칙 (실무진이 읽는다)

- 첫 줄에 결론. 제목은 발견("~가 낡았다")이 아니라 결과("~가 된다")로
- 본문에 파일 경로·커밋 해시·워크스페이스 번호(w2 등)·에이전트 이름을 쓰지 않는다.
  담당은 역할명(개발·제작·음악·세계관·운영·기획)으로. 필요하면 맨 아래 `참고` 에만
- 저장소 내부 문제(문서 낡음·미추적 파일 등)는 Notion 에 올리지 않는다
- 홈 본문은 **부분 수정만.** 통째 교체는 자식 페이지·DB 를 휴지통으로 보낸다 (2026-09-13 사고)
- 기존 페이지는 지우지 않고 `보관` 아래로 옮긴다

## 구조

**IP 층** — 게임과 무관한 원본

| DB | 한 페이지 = | 담당 |
|---|---|---|
| 캐릭터 | 캐릭터 한 명 | 제작(builder) 초안 · 세계관(lore) 보강 |
| 곡 | 곡 하나 | 음악(composer) |
| 설정 사전 | 지역·세력·개념·규칙·아이템 하나 | 세계관(lore) |
| 사건 연표 | 세계관 속 사건 하나 | 세계관(lore) |
| 스토리 | 시즌·아크 하나 | 세계관(lore) |
| 용어집 | 용어 하나 | 세계관(lore) |

**매체 층** — 게임 · 콘텐츠(소설 한 화·SNS 영상·이벤트) · 업데이트(게임 업데이트·가챠 배너)

**운영 층** — 로드맵 · 업무 보드 · 결정 로그 · 버그

구조·템플릿·작성 규칙의 관리자는 운영(ops).

### 캐릭터 페이지

- 속성: 이름 · 영문 표기 · 등급 · 성별 · 나이대 · 진영(→설정 사전) · 컨셉 한 줄 · 성격 키워드 ·
  대표 색 · 상징물 · 제작 상태(기획/제작/출시) · 출시일 · 정사 · 테마곡(→곡) · 관계 캐릭터(→캐릭터)
  · 등장 게임(→게임, 3단계에 추가)
- 본문 템플릿: 대표 일러스트 / 외형(헤어·눈·의상·실루엣·**하지 말 것**) / 성격 / 말투·대사 예시 /
  **목소리**(톤·음역·말버릇) / 배경 스토리 / 게임별 능력(플레이어 언어로) / 음악 방향 / 변경 이력

### 곡 페이지

- 속성: 제목 · 캐릭터(→캐릭터) · 용도(테마곡/이벤트곡 등) · 상태(작사/생성/채택/사용 중) ·
  스타일 프롬프트 · Suno 링크 · 사용처 · 정사
- 본문: 가사 · 작사 의도
