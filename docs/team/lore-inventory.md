## 1. 설정 사전 후보

### 지역·층

| 항목명 | 종류 | 출처 한 줄 |
|---|---|---|
| TRASH | 지역 | 운영 체제의 휴지통. 삭제됐지만 아직 영구 삭제되지 않은 데이터가 의식을 갖고 사는 공간 (WB §1) |
| 상층 — 낙하 구역 | 지역 | Garbage Collector 가 떨어지는 구역. 게임 화면에 해당 (WB §4) |
| 중층 — 달리는 구역 | 지역 | 존재들이 달리는 구역. 플레이어 영역 (WB §4) |
| 하층 — 심층부 | 지역 | GATE 가 있는 곳. 게임 미구현, 서사상만 존재 (WB §4 · GATE-001 "공간 아래에 다른 층") |
| GATE | 지역(구조물) | TRASH 에서 SYSTEM 으로 돌아가는 유일한 출구. "크지 않았다. 빛나지도 않았다. 그냥 문이었다" (WB §3·§5 · D2 LEGACY-0006) |
| SYSTEM | 지역(상위 층) | 삭제 명령을 내리는 곳. 이야기 속 "천장". 실은 CPU 의 한 프로세스 (WB §4) |
| OS / Kernel | 지역(상위 층) | SYSTEM 과 CPU 사이 층. 이름만 있고 설명 없음 (WB §4) |
| CPU — 연산층 | 지역(상위 층) | 모든 것을 처리하지만 이해하지 않는 층 (WB §4·§7) |
| Storage — 영구 저장층 | 지역(상위 층) | 삭제 이전 데이터까지 기억하는 층 (WB §7) |
| RAM — 휘발 임시층 | 지역(상위 층) | 전원이 꺼지면 사라지는 층 (WB §7) |
| Hardware — 물리 기판 | 지역(최상위 층) | 하드웨어 신들이 존재하는 층 (WB §4) |

### 개념

| 항목명 | 종류 | 출처 한 줄 |
|---|---|---|
| 삭제 | 개념 | 모든 캐릭터가 받은 명령. "없는 것처럼 취급됐지만 여기 있다" (TH 테마1) |

| Restore — 복원 | 개념 | GATE 를 통과해 시스템으로 재통합. TRASH 쪽에서 보면 소멸일 수 있다 (WB §3·§5 · TH 테마3) |
| Cycle — 사이클·루프 | 개념 | 공간 전체가 주기적으로 초기화되는 것. 게임의 한 판 (WB §2·§3) |
| Integrity — 무결성 | 개념 | 공간의 안정도. 달릴수록 유지 (WB §2·§3) |
| 잔향 (echo) | 개념 | 기억은 없지만 무언가 남는 느낌 (TH 테마2 · D1 TRASH-012) |
| 복원율 | 개념 | 손상된 기록이 얼마나 읽히는지. 레거시 로그의 형식 장치 (SS Phase 2 · D2) |
| 비정형 안정 패턴 | 개념 | CPU 가 TRASH 메모리에서 처음 감지하는 자가 조직 패턴 (WB §7) |
| CPU 의 자각 | 개념 | 처리와 인식은 다르다 — CPU 가 처음 인식하기 시작하는 순간 (WB §7 · SS 이후) |
| 연말 대청소 | 개념(절기) | 12~1월 GC 강화. "이 공간의 겨울" (TH 이벤트 시즌) |
| 계절별 GC 변화 | 개념(절기) | 봄=새 사이클·시드 / 여름=GC 느려짐 / 핼러윈=손상된 존재 증가 (TH 이벤트 시즌) |

## 4. 용어집 후보

| 용어 | 한 줄 정의 (출처 문구 기준) |
|---|---|
| TRASH | 이 공간 전체. 삭제됐지만 아직 사라지지 않은 곳 |
| Garbage Collector (GC) · 정리 프로세스 | 위에서 떨어지는 청소 작업. 게임의 장애물(똥) |
| Cycle · 사이클 · 루프 | 공간의 리셋 주기. 게임의 한 판 |
| CYCLE COUNT | 사이클 번호를 찍는 시스템 로그 표기 (예: 0010) |
| GATE | 유일한 출구. 복원 경로 |
| Purge | 영구 삭제 |
| Restore · 복원 | GATE 를 통과해 시스템으로 돌아가는 것 |
| Fragment · 조각 | 수집 가능한 데이터 잔해 |
| Integrity · 무결성 | 공간의 안정도 |
| 잔해 (일반·금·다이아·토파즈·무지개) | 떨어지는 데이터. 게임에서는 똥 |
| 복원율 | 손상된 기록이 읽히는 비율 |
