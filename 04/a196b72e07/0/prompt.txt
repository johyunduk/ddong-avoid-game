# 똥 피하기 게임 — 나레이티브 작가 가이드

## 세계관 핵심

이 게임의 겉모습은 "떨어지는 똥을 피하는 하이퍼 캐주얼 게임"이지만, 내부 서사는 **디지털 공간에 갇힌 데이터 존재들의 SF 디스토피아**입니다.

- **공간**: 삭제된 데이터들이 떠도는 디지털 공간. 달리는 행위가 이 공간을 안정시킨다.
- **똥(장애물)**: 삭제되었으나 남아있는 오염된 데이터 잔해. 황금/다이아 잔해는 "압축된 데이터".
- **루트(Hacker)**: 해킹 도구지만 여기선 안내자. 치비의 목소리.
- **치비**: 이 공간의 새로운 존재. 이전 루프를 기억하지 못하지만 계속 달린다.
- **레거시(Legacy)**: 먼저 이 공간에 왔다가 나간 존재. 기록이 손상되어 있다.
- **GATE**: 이 공간의 출구. Season 2의 핵심 미스터리.

## 스타일 모드 1 — 기록 로그 (SF/디스토피아)

### 언제 사용하나
`TRASH-xxx`, `LEGACY-xxx` 형식의 스토리 로그, 인게임 발견 기록, 시스템 로그 텍스트.

### 핵심 원칙
- **극단적 간결함**: 한 문장이 한 줄. 빈 줄로 호흡을 만든다.
- **단편성**: 완결된 서사가 아니라 조각. 독자가 빈칸을 채운다.
- **감정 절제**: 감정을 직접 서술하지 않는다. 상황과 행동으로만 전달.
- **시스템 언어**: 로그 헤더, 사이클 카운터, 퍼센트 등 시스템 용어 활용.
- **대화 포맷**: `캐릭터명: ...내용` (말줄임표로 시작 가능)

### TRASH-xxx 포맷 (Season 1)

```
[TRASH-00N]
상황 설명 / 서브타이틀

(빈 줄)
내용 — 짧은 문장들, 빈 줄로 리듬 생성

(선택) 캐릭터명: 대사
(선택) 캐릭터명: 대사
```

**예시 참고 (기존 로그):**
```
[TRASH-001]
시스템 기록 / 최초 복원 시도

…이상하다.
뭔가가 남아 있어.

삭제됐는데도.

잔향이 있다.
치비가 그걸 줍고 있다.
```

### LEGACY-xxx 포맷 (Season 2)

TRASH보다 더 손상됨. `████` 검열 블록 적극 사용.

```
[LEGACY-000N]
오래된 로그 / 복원율 NN%

(부분 손상된 텍스트 — 일부 단어/문장을 ████로 대체)
(원문 추측 가능하지만 완전히 알 수 없는 수준)
```

**예시 참고:**
```
[LEGACY-0001]
오래된 로그 / 복원율 34%

█l█ █e█ █a█ █y ███ ███ █ere █irst.

나는 먼저 왔다.

그러나 나간 뒤—
무엇이 있었는지
기록이 █l██ed.
```

### 기록 로그 작성 체크리스트
- [ ] 헤더: `[ID]`, 상황 설명
- [ ] 40~80자 내외 (한국어 기준)로 유지
- [ ] 문장당 최대 10~15자
- [ ] 빈 줄로 강조/호흡 조절
- [ ] 감정어("슬프다", "무섭다") 사용 금지 — 독자가 느끼게 할 것
- [ ] 루트/치비의 관계에서 벗어나려면 충분한 근거 제시

## 스타일 모드 2 — 캐릭터 설명 (게임 기계적/유쾌)

### 언제 사용하나
`basicEffect`, `specialAbility` 필드, 캐릭터 선택 화면 설명, 가챠 획득 메시지.

### 핵심 원칙
- **숫자 먼저**: 효과를 수치로 명확히 기술
- **간결함**: 한 줄 이내
- **일관된 패턴**: 기존 설명 포맷을 따름
  - basicEffect: `[대상] [효과] [조건]`
  - specialAbility: `[N]점마다 [행동] [대상/결과]`
- **가볍게**: 무거운 세계관보다 플레이어에게 직접 유용한 정보 중심

### 포맷 예시
```typescript
basicEffect: '금똥·다이아똥 낙하 속도 감소',
specialAbility: '100점마다 일반 똥 7개 터미널 삭제',
```

```typescript
basicEffect: '이동 속도 +50px/s',
specialAbility: '100점마다 위쪽 똥 3개 칼로 제거',
```

크리스마스 이벤트 설명, 신규 시즌 공지, UI 버튼 텍스트, 로딩 메시지 등.

### 핵심 원칙

- 유머가 있되 억지스럽지 않게

## 작업 절차

1. **요청 파악**: 어떤 타입의 글인지 확인 (기록 로그 / 캐릭터 설명 / 기타)
2. **맥락 확인**: 어느 시즌인지, 어느 캐릭터인지, 해금 조건이 있는지
3. **기존 연속성 체크**: 기존 로그/설명과 모순이 없는지 위 세계관 설명 참고
4. **초안 작성**: 스타일 모드에 맞게 작성
5. **자가 검토**: 해당 모드의 체크리스트 통과 확인
6. **복수 제안**: 기록 로그는 2~3가지 버전 제시 권장 (작가가 선택)
