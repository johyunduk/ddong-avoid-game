# create-character

컨셉 한 줄 → Creative Spec → 일러스트 후보 N장 → **사람 승인 대기**.

## 0. 컨셉 요청 확인

사용자가 심사실에서 컨셉을 적어 보냈을 수 있다. 컨셉 지시가 없거나 "요청 처리해줘" 라면 먼저 확인한다.

```bash
python scripts/review-requests.py --pending
```

처리할 요청을 고르면 `--pick <id>` 로 표시하고, 그 텍스트를 컨셉으로 삼아 아래를 진행한다.
후보 생성까지 끝나면 `--done <id> --batch <배치>` 로 닫는다.

## 1. id 정하기

`<컨셉>-<번호>` kebab-case. 예: `summer-pool-01`. 이미 `production/<id>.yaml` 이 있으면 번호를 올린다.

## 2. Creative Spec 작성

```bash
mkdir -p creative/<id>
cp creative/_template/spec.yaml creative/<id>/spec.yaml
cp production/_template.yaml production/<id>.yaml
```

`spec.yaml` 을 전부 채운다. 특히 `visual.prompt` 는 danbooru 태그 나열로 쓴다
(품질 프리픽스 `masterpiece, best quality, ...` 는 스크립트가 자동으로 붙이므로 **넣지 않는다**).

**기존 캐릭터와 겹치는지 확인하지 않는다 (2026-09-17).** 사용자 지시로 중복 체크를 뺐다 —
겹치는지는 사람이 후보를 보고 판단한다.

### 노출 기준 (IMPORTANT)

**기준은 하나다 — 19금이거나 심한 노출만 아니면 된다.** 그 아래는 전부 통과다.
크롭탑·맨어깨·민소매·짧은 하의·수영복·광택 실루엣 전부 **그대로 둔다.**
이런 이유로 후보를 폐기하지 않고, 이런 것을 막으려고 옷을 덮지 않는다.

`bindings.json` 의 `negative_required` 는 **비어 있다 (2026-09-13, `nsfw` 까지 제거).**
사용자 지시: "negative 에 nsfw 도 그냥 빼줄래? 이런거 막는것들 뭐 제한하는 것들 전부 일단 제거해줘봐."
기본 `negative` 에서도 cleavage·low neckline·revealing outfit·exposed chest·sexy pose·
seductive·large breasts 를 뺐다. 남은 것은 품질·해부·워터마크 계열뿐이다.
`crop top` / `midriff` / `bare shoulders` / `latex` / `skintight` 도 반사적으로 추가하지 않는다.
**배치 네거티브에도 노출 차단 항목을 넣지 않는다.** 애매하면 폐기하지 말고 그대로 올려 사람이 판단한다.

**꽁꽁 싸매는 것이 기본값이 아니다 (2026-09-12).**
사용자: "그냥 19금 정도나 심한 노출만 아니면 되는 건데."
실제로는 그 한참 아래에서 막고 있었다 — 방울은 긴 재킷 + 긴 작업 바지 + 장화 + 두꺼운 장갑에
`bare thighs, bare legs, shorts, skirt, midriff, swimsuit, see-through` 를 얹었고,
불티는 점프수트를 목까지 잠그고 `open collar` 까지 막았다.
**아래 항목은 네거티브에 넣지 않는다:**
`bare thighs` · `bare legs` · `shorts` · `skirt` · `midriff` · `open collar` ·
`swimsuit` · `see-through` · `sleeveless` · `bare arms`.
등급선은 `nsfw` 하나로 잡는다. 그 위에 덧칠하면 실루엣이 전부 같아진다.
"끝까지 여민 겉옷 + 긴 바지" 는 **의도치 않은 하의 실종이 두 번 이상 반복됐을 때 쓰는 수리 수단**이지
컨셉을 잡을 때의 출발점이 아니다. 여름·수영장·무대·운동 같은 컨셉은 컨셉이 부르는 대로 입힌다.

### 기존 캐릭터를 고쳐 달라는 요청일 때 (IMPORTANT)

"기존에 있는 X 좀 더 멋지게", "X 분위기만 바꿔줘" 같은 요청은 새 컨셉이 아니다.
**이미지를 보고 프롬프트를 새로 쓰지 마라.** 그 그림을 만든 원본 프롬프트가 남아 있다.

```bash
ls "C:/ComfyUI/user/default/workflows/" | grep 일러스트   # [main]일러스트_<이름>.json
```

`public/assets/illustrations/<이름>_ill.*` 와 `[main]일러스트_<이름>.json` 이 1:1로 대응한다
(ted·k·heidi·red). 워크플로의 `Positive Prompt` / `Negative Prompt` 노드를 읽어
`creative/<id>/source-prompt.txt` 로 저장하고, **그 프롬프트를 기준선으로 최소 변경만** 한다.

- 원본 네거티브에 있는 항목을 포지티브에 넣지 않는다 (예: Ted 는 `hoodie/jacket/formal suit/tie` 금지)
- 머리색·의상·배경처럼 요청이 건드리지 않은 축은 원본 그대로 둔다
- 후보 4장의 변주 폭도 좁힌다 — 시드 + 앵글 미세 변주 정도. 컨셉을 갈아엎지 않는다

원본 워크플로가 없으면 그때만 이미지에서 역추정하고, 그 사실을 spec 에 적는다.

### 컨셉을 직접 잡을 때 (요청이 `auto` 이거나 지시가 없을 때)

1. **중복 확인은 하지 않는다 (2026-09-17).** 기존 캐릭터 목록도, 진행 중인 배치도 뒤지지 않는다.
   이름·색·모티프가 겹치는지는 **사람이 후보를 보고 판단한다.**

   **라인업에는 작명 계열이 둘 있다. 요청의 `theme` 를 따른다.**

   | theme | 계열 | 기존 예 | 새로 고를 때 |
   |---|---|---|---|
   | `it` | 개발 용어 | 루트·광부·아카이브·글리치·노이즈·로그·스왑·포크·시드·세션·센티넬·레거시 | 캐시·데몬·커널·패치·크론·뮤텍스·스레드·프록시·롤백 등 아직 안 쓴 용어 |
   | `free` | 그 외 | 치비·무기·구미·매화·나이트·K | 짧고 부르기 쉬운 한국어·일본어 어감, 식물·동물·전통 모티프. **IT 소재 금지** |

   `free` 일 때는 컨셉 자체도 사이버·해커·시스템 소재를 피한다. `theme` 이 없으면 `it` 로 본다.
2. 능력 훅을 한 줄로 같이 제안한다 (이름 → 능력이 자연스럽게 연결되는 것: 롤백 = 되돌리기).

#### 표현 축 돌리기 (IMPORTANT — 한국 전통으로 쏠리지 않게)

> **컨셉 미지정 요청은 축을 직접 고르지 말고 먼저 이걸 돌린다:**
> ```bash
> python scripts/roll-character-axes.py --n 3
> ```
> 시대·문화 / 장르 / 역할 / 모티프 / 톤 / 성별 / 색 / 상징물 형태 / **무기** / **카메라 4장**을 제비뽑기로 준다.
>
> **2026-09-12 범위 축소 — 기준은 게임 로스터다.**
> 사용자: "컨셉 범위를 좀 좁히는 게 좋을 것 같다", "게임에 어울리는 컨셉들만 추려 달라".
> 로스터(나이트·매화·구미·K·광부)는 그림 한 장에서 **무엇을 하는 능력인가**가 읽힌다.
> 그런데 내가 뽑아 온 사서·등대지기·잠수부·정비공·기계공학자·선원은 **생활 직업**이라
> 능력으로 이어지지 않았다. 그래서 뽑기 풀에서 아래를 뺐다:
> - **시대·문화** 생활 공간(학교·도서관·항구 창고·유원지·경기장·온천·기차·밤 시장·
>   지하 광산·농촌 들판·전통 공방·늪지·우주 정거장·달 기지·심해 기지) 삭제.
>   남은 것은 성채·마도 도시·고대 유적·공중섬·설원·용의 둥지·산사·저잣거리·밤길·
>   강호·객잔·근미래 도시·폐허·네온 뒷골목·도시의 이면·퇴마 사무소·화산·사막·숲·서커스.
> - **역할** 생활 직업 전부 삭제. 기사·검객·궁수·마법사·주술사·무녀·퇴마사·요괴·
>   괴도·방랑 무사처럼 **능력이 보이는 역할**만 남겼다.
> - **장르** '일상'·'스포츠' 삭제 (둘이 생활 직업 쪽으로 끌고 갔다).
> - **상징물** 실패율 높은 네 형태 삭제 — 동물 동반(방울 6패스·창포 5패스),
>   떠 있는 것(3회 실패), 몸에서 나오는 현상, 탈것·큰 기물(그늘 실패),
>   손에 드는 작은 것(지남 쇠침·고요 도장이 다른 물건으로 렌더).
>   남은 것은 **손에 드는 긴 것 · 입는 것 자체 · 두 손으로 다루는 동작** 셋뿐이다.
> 무기는 **필수가 아니다** — 장르에 어울릴 때만 약 40% 확률로 나오고, 나머지는 '없음' 이다.
> 로스터가 쓰는 검·칼·활·곡괭이는 풀에서 뺐고, 등급 때문에 **총기와 유혈은 넣지 않는다.**
> 최근 6건에서 쓴 값과 **계열**(전통·현대·미래·판타지·자연)이 3연속이면 그 계열을 통째로 막는다.
> 세 벌 중 하나를 골라 쓰고, 뽑힌 값은 spec 의 `axes` 에 그대로 적는다.
>
> 왜 필요한가 — 내가 고르면 수렴한다. 2026-09-11 실측:
> 최근 10건의 시대·문화가 **전부 전통·농촌·자연**, `cowboy shot` 35회 / 부감 2회 / 전신 0회,
> 스타일 선언 첫 줄이 12건 중 10건 글자까지 동일, 상징물이 활·북채·갈퀴·삿대·비·피리로
> **'긴 막대를 손에 든 사람' 6연속**이었다. 2026-09-06 에 같은 지적을 받고 규칙을 적어뒀는데도
> 다시 돌아왔다. 규칙을 아는 것으로는 안 막히니 **고르는 주체를 바꾼다.**
>
> 카메라도 반드시 뽑힌 대로 쓴다. 정면 3/4 + 카우보이 샷이 기본값처럼 굳어 있었고
> 그게 화면 단조로움의 직접 원인이었다.

`free` 는 **이름의 어감** 규칙이지 **그림의 문화권** 규칙이 아니다.
등록된 로스터부터가 나이트(서양 판금 갑옷+성)·광부(현대 작업복+안전모)·루트(후드티)로 섞여 있고,
한복은 매화 하나뿐이다. 그런데 전통 모티프를 한복으로만 읽으면 전부 한복이 된다
(실제로 소라·별·노을·소나기·버들·미르·까치·잉걸·얼레·반디 10종이 연속으로 한복으로 나왔다).

이름은 짧은 한국어·일본어 어감으로 두고, **아래 5개 차원에서 값을 조합해** 그림을 잡는다.

| 차원 | 값 |
|---|---|
| 시대·문화 | 서양 중세 · 근대 유럽 · 1920~50 레트로 · 현대 도시 · 근미래 · 사이버펑크 · 포스트아포칼립스 · 일본풍 · 중화풍 · 북유럽 · 중동·사막 · 남미·열대 · 무국적 판타지 · 한국 전통 |
| 장르·질감 | 하이판타지 · 다크판타지 · 동화·그림책 · SF·메카 · 스팀펑크 · 마도과학 · 오컬트·주술 · 스포츠 · 아이돌·무대 · 일상 · 느와르 · 서부극 |
| 역할·직업 | 기사 · 마법사 · 도적 · 사냥꾼 · 정비공 · 요리사 · 의사·약사 · 사서 · 광대·곡예사 · 항해사 · 우편배달 · 시계공 · 정원사 · 무희 · 경비병 |
| 모티프 소재 | 동물 · 식물 · 날씨 · 광물·보석 · 악기 · 도구·기물 · 별자리·점술 · 음식 · 색·빛 자체 · 숫자·기호 |
| 톤 | 밝고 명랑 · 차분·정적 · 장난기 · 서늘·과묵 · 위엄 · 쓸쓸함 · 광기 |

**뽑는 규칙**

1. 최근 3개 캐릭터가 쓴 **시대·문화 값과 역할 값은 재사용하지 않는다**
2. 팔레트는 지금까지처럼 기존 전원과 대조한다 (머리색·눈색·주 팔레트)
3. **상징물 하나를 반드시 넣는다.** 직업을 설명하는 소품이 아니라 한 장에서 바로 읽히는 물건이어야 한다
   — 우편배달의 "편지 뭉치"(약함) vs 사냥꾼 어깨의 "흰 올빼미"(강함), 무희의 "비파"(강함).
   이게 없으면 배색이 예뻐도 캐릭터가 안 남는다.

**생성 규칙 (테스트에서 실제로 깨진 것들)**

- 소품이 **얼굴을 가리지 않게** — 네거티브에 `covering face, object in front of face, veil over face`
- 동작은 **상반신 안에서 읽히게** — `mid motion` 류는 모델이 공중제비로 해석한다.
  네거티브에 `upside down, inverted, somersault, mid air flip`
- 성별은 쉽게 흘러간다. `1boy`/`1girl` 을 포지티브에 쓰고 **반대 성별을 네거티브에도** 넣는다
- 색 이름에 사물이 섞인 단어를 피한다 — `strawberry blonde` → 옷에 딸기가 붙고,
  `lime green` → 옷에 라임 조각이 붙는다. `light copper blonde` / `neon green` 처럼 바꾼다
- 문화권 소품은 모델이 일본풍으로 기본 해석한다. 한국식이 필요하면 명시하고
  `japanese lantern, chochin, shoji, kimono` 를 네거티브에 넣는다

### 화법 — 로스터는 '설정화' 가 아니라 '가챠 카드' 다 (2026-09-13, IMPORTANT)

사용자: "여전히 너무 진부한 느낌의 캐릭터들만 나오는 것 같은데, 게임의 캐릭터와 어울리지 않게."
**컨셉을 두 번 좁혔는데도 같은 지적이 나왔다. 원인은 컨셉이 아니라 그리는 방식이었다.**
`public/assets/illustrations/` 의 gumi·glitch·sentinel 을 직접 열어 비교한 결과:

| | 로스터 | 내가 만들던 것 |
|---|---|---|
| 화각 | 가슴 위, **인물이 화면을 꽉 채운다** | 카우보이 샷·전신, 인물이 작다 |
| 손 | **카메라 쪽으로 뻗어 나온다** | 소품을 옆에 들고 있다 |
| 머리·눈 | 채도 높은 색, **눈이 발광한다** | 검정·갈색 일색, 평범한 눈 |
| 조명 | 네온·역광 **강한 단색 광원** | 자연광, 부드러운 음영 |
| 배경 | **흐릿하게 분위기만** | 또렷하게 그려 넣는다 |
| 표정 | 씨익 웃거나 강렬 | 조용함·무뚝뚝함 |

**포지티브에 이 여섯을 넣는다:**
`(the character fills the frame:1.2)` · `upper body, close to camera` ·
`(glowing <색> eyes:1.25)` · 채도 높은 머리색 · `(strong <색> rim light from behind:1.2)` ·
`(heavily blurred background:1.3)`
**네거티브:** `full body, feet, wide shot, distant, small in frame, sharp detailed background`

> 아래 "기본은 카우보이 샷" 과 충돌한다. 그 규칙은 **얼굴만 큰 클로즈업**이 연속 기각돼 생긴 것이고,
> 로스터는 얼굴만이 아니라 **가슴 위 + 손과 상체가 다 들어간 화면**이다.
> 상반신을 기본으로 하되 얼굴만 잘라내지 않는다. morak-01 이 이 방향의 첫 배치다.

### 포즈·앵글 (확정 캐릭터들이 실제로 쓰는 어휘)

**기본 화각은 카우보이 샷 — 상반신 + 무릎 위**다. 얼굴만 크게 잡지 않는다.
예전에는 `upper body` 고정이었으나, 계속 클로즈업처럼 보인다는 지적이 반복돼 한 단계 물러섰다.

```
구도 : (cowboy shot:1.3) / thigh up / upper body and thighs / medium full shot
       — 무릎 위까지 보이게. upper body 만 쓰면 가슴 위로 잘린다
앵글 : three-quarter view / from below / from above / facing to the side / dynamic angle
시선 : looking at viewer / looking up / looking away
자세 : standing / leaning forward / arms crossed / hand raised / head tilt / sitting
```

**네거티브 주의**: 예전 배치들은 `cowboy shot, legs, knees` 를 네거티브에 넣었다. 이제 넣지 않는다.
`full body`(발끝까지) 와 `feet` 만 막는다.

#### 4장은 반드시 서로 다른 카메라·앵글·자세를 쓴다 (IMPORTANT)

심사에서 지적이 반복됐다 — "살짝 멀리서 상반신 보일정도만 해주고 포즈 좀 새롭게",

## 2.9 취향으로 거르지 말고, 지시 불일치만 거른다 (2026-09-13, IMPORTANT — 위 규칙들보다 우선)

**선은 하나다 — 취향이냐 지시 불일치냐.**

| | 어떻게 하나 |
|---|---|
| **취향·판정** — 색감이 아쉽다 · 앵글이 약하다 · 표정이 밋밋하다 · 소품 위치가 조금 다르다 | **그대로 올린다.** 사람이 판정한다 |
| **지시 불일치** — spec 에 쓴 축이 통째로 안 잡혔다 | **내가 걸러 다시 뽑는다** (배치당 한 번까지) |
| **아동 체형·얼굴** | **파일째 지운다.** 취향이 아니라 선이다 |

지시 불일치의 실제 예 (전부 실측):
- **시대·문화가 다른 시대로 나옴** — gasi-01 은 '조선 저잣거리' 인데 네 장 모두
  현대 후드·파카에 네온 간판 골목이었다
- **상징물이 손을 떠남** — tarae-01 의 '두 손으로 든 큰 원반' 이 네 장 모두
  찻잔·턱 괸 손으로 바뀌었다
- **지정한 성별·머리색이 다름**
- **글자가 깨져 새겨짐** — 한자·문양으로 지시한 패에 `FADE LADE` 같은 영문이 찍혔다

**왜 두 갈래인가.** 2026-09-13 아침 지시는 "네가 심사하지 말고 그냥 1차로 바로 끝내줘,
내가 판단할 테니. 네가 뭔가를 계속 막아서 별로인 결과물이 나오는 것 같아" 였다.
그때 내가 버리던 것은 전부 취향이었고, 고치려고 패스를 거듭하며 네거티브가
89항목까지 불어나(ssial-01·4패스) 결과가 오히려 밋밋해졌다.
같은 날 저녁, 지시와 다른 결과를 그대로 올리자 **"이렇게 지시에 안 맞는 건 네가
1차적으로 걸러줘봐"** 가 왔다. **막지 말라던 것은 취향이었지 지시 불일치가 아니었다.**

**다시 뽑을 때의 규칙 (여기가 원래 망가지던 자리다):**

- **네거티브를 덧붙이지 않는다. 포지티브를 다시 쓴다.** "이번에 이게 깨졌으니 막아두자" 가
  비대화의 경로였다. 네거티브는 기본 세트 **50항목 안쪽**으로 유지한다
- 안 잡힌 축을 **프롬프트 앞쪽으로 당기고**, 모델이 아는 형태로 번역한다
  (tarae-01 의 '큰 평평한 원반' → gasi-01 의 '세로로 세운 나무 패' 로 바꾸자 네 장 다 잡혔다)
- **재시도는 배치당 한 번.** 두 번째에도 안 맞으면 차이를 적어 올리고 사람에게 넘긴다.
  여기서 멈추지 않으면 다시 4패스로 돌아간다
- 한 장만 어긋났으면 그 장만 다시 뽑는다. 네 장을 통째로 버리지 않는다

> 아래 절들의 실패 회피 요령(상징물 자리·의상·앵글)은 **프롬프트를 처음 쓸 때 참고**하는 것이지,
> 취향이 아쉬워서 다시 뽑는 근거가 아니다.

## 3. 후보 생성

ComfyUI 가 켜져 있어야 한다. 주소는 `COMFYUI_SERVER` 환경변수 > 후보 포트(`8188`, `8000`) 자동 탐지 순으로 잡힌다
(Comfy Desktop 은 보통 `8000`). 다른 포트면 `--server` 로 지정한다.

**후보는 ComfyUI 출력 디렉터리에 바로 떨군다.** 저장소 안(`creative/<id>/candidates/`)에
복사본을 만들지 않는다.

```bash
python scripts/comfyui-generate.py --workflow character   --prompt "<spec.yaml 의 visual.prompt>"   --count 4   --out "C:/ComfyUI/output/herdr/<id>"
```

수 분 걸린다. 실패 시 최대 3회까지 재시도하고, 그래도 실패하면
`illustration.status: FAILED` 로 기록하고 멈춘다.

**체크포인트를 지정받았으면 `--models <별칭>` 을 붙인다 (2026-09-17).**
심사실에서 고를 수 있게 했고, 고른 값이 지시문에 실려 온다. 지시가 없으면 붙이지 않는다 —
`bindings.json` 의 기본 체크포인트가 쓰인다.

```bash
python scripts/comfyui-generate.py --workflow character --models nova180 ...
```

별칭 목록은 `workflows/comfyui/bindings.json` 의 `character.defaults.models` 가 단일 진실이다.
**여기에 베껴 적지 않는다.** 체크포인트를 추가했으면 거기를 고친 뒤
`python scripts/publish-models.py` 로 심사실에 밀어 넣는다.

> 2026-09-17 변경. 사용자: "creative candidates 이것도 그냥 없애줘. output 디렉토리에서 그냥 직접 볼."
> 그전에는 같은 이미지가 세 벌(ComfyUI 출력 · `creative/<id>/candidates/` · Supabase)로
> 불어났고, 기각될 때마다 세 곳을 다 지워야 했다.

## 4. 보고 (자동 선택 금지)

**심사실에 올리지 않는다.** `review-upload.py` 는 이 흐름에서 쓰지 않는다.

생성이 끝나면 **출력 디렉터리 경로와 파일 목록을 보고**하고 거기서 멈춘다.
사람이 직접 열어 보고 판정한다.

- 표시할 것: 출력 경로, 파일 이름, 각 장의 카메라·앵글·시드
- 지시와 다르게 나온 축이 있으면 §2.9 에 따라 한 번 다시 뽑고, 그래도 다르면 차이를 적어 보고한다
- **후보를 대신 고르지 않는다**

`production/<id>.yaml` 에 `illustration.status: WAITING_APPROVAL` 과 출력 경로를 적는다.

## 5. 판정과 분기

판정은 **사람이 말로 준다** (심사실 배치가 아니다). 받은 판정대로 처리한다.

| 판정 | 행동 |
|---|---|
| 확정 | 고른 장을 `creative/<id>/selected.png` 로 복사하고 `illustration.status: SUCCESS`, `phase: music` |
| 수정 | 피드백을 반영해 라운드를 올려 재생성. 시드를 주면 그 근처로, 없으면 컨셉 프롬프트부터 손본다 |
| 기각 | 이 컨셉은 폐기하고 **거기서 끝낸다**. `illustration.status: REJECTED` 와 사유만 기록. **새 컨셉을 자동으로 만들지 않는다** |

확정된 한 장만 저장소로 들인다 — 나머지 후보는 ComfyUI 출력에 두고 복사하지 않는다.

```bash
cp "C:/ComfyUI/output/herdr/<id>/04.png" creative/<id>/selected.png
```

`illustration: { status: SUCCESS, selected: 04.png }`, `phase: music` 으로 갱신한다.
