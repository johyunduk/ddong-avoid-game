# Karpathy LLM Wiki — Claude Code 설정 가이드

## 기존 프로젝트에 추가하는 방법

기존 프로젝트 코드나 노트는 **그대로 두면 됩니다.** 새로운 `raw/`와 `wiki/` 폴더를 추가하고, 기존 파일들을 점진적으로 소화(ingest)시키면 됩니다.

### 폴더 구조 (기존 프로젝트 기준)

```
your-project/
├── src/                  ← 기존 코드 (손대지 않음)
├── docs/                 ← 기존 문서 (손대지 않음)
├── raw/                  ← 새로 추가 (원본 소스를 여기에 복사)
│   ├── decisions/        ← 설계 결정 기록
│   ├── references/       ← 참고 자료
│   └── notes/            ← 기타 노트
├── wiki/                 ← 새로 추가 (LLM이 자동 생성/관리)
│   ├── index.md          ← 전체 목차 (LLM이 관리)
│   ├── log.md            ← 작업 기록 (LLM이 관리)
│   └── concepts/         ← 개념 페이지들 (LLM이 생성)
└── CLAUDE.md             ← 새로 추가 (가장 중요!)
```

```markdown
각 wiki 페이지는 다음 형식을 따릅니다:
- title, summary, tags, sources, content, related

## 워크플로우
- ingest  : raw/ 소스를 읽고 wiki/ 페이지 생성/업데이트
- query   : wiki/ 기반으로 질문에 답변 (출처 명시)
- audit   : 모순/중복/고아 페이지 탐지
```

---

## 기존 파일 처리 방법

### Step 1: 기존 파일 분류

| 파일 종류 | 처리 방법 |
|---|---|
| 설계 문서, ADR | `raw/decisions/`에 복사 |
| README, 기술 노트 | `raw/notes/`에 복사 |
| 외부 참고 자료 | `raw/references/`에 복사 |
| 소스 코드 | 직접 복사 X → Claude가 읽도록 경로만 알려줌 |

> **원본 파일은 절대 이동/삭제하지 마세요.** `raw/`에는 복사본만 넣습니다.

### Step 2: 일괄 ingestion 프롬프트

```
raw/ 폴더에 있는 모든 파일을 순서대로 wiki에 컴파일해줘.
각 파일마다:
1. 핵심 개념/결정 추출
2. wiki/ 에 해당 페이지 생성 또는 기존 페이지 업데이트
3. log.md에 처리 기록 추가
끝나면 index.md 전체 업데이트해줘.
```

### Step 3: 코드 자체를 소스로 활용

```
src/ 폴더의 코드를 읽고, 주요 아키텍처 결정과
패턴들을 wiki/concepts/ 에 정리해줘.
```

## 일상적인 사용법

### 소스 추가 (새 문서/노트가 생길 때마다)

```
raw/notes/2026-05-25-new-decision.md 를 wiki에 ingest해줘
```

### 질문하기

```
wiki에서 [개념/기능]에 대해 설명해줘
인증 관련 설계 결정들 요약해줘
A와 B의 차이점이 뭐야?
```

### 정기 감사 (월 1회 권장)

```
wiki 전체를 감사해줘:
- 서로 모순되는 내용
- 오래된 정보
- 링크 없는 고아 페이지
- 언급됐지만 페이지 없는 개념들
```

## RAG vs LLM Wiki 비교

| 구분 | RAG (기존 방식) | LLM Wiki |
|---|---|---|
| 동작 방식 | 질문마다 문서 재검색 | 한 번 컴파일 → 계속 쿼리 |
| 지식 축적 | 없음 | 소스가 쌓일수록 연결됨 |
| 세션 간 기억 | 없음 | CLAUDE.md + wiki/ 파일로 유지 |
| 복잡한 질문 | 5개 문서 동시 검색 어려움 | 이미 연결된 페이지에서 답변 |
